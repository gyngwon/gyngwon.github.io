01 · flagship

Credit Risk Data Pipeline

Raw loan-level data → tested dbt Star Schema → orchestrated pipeline → Power BI dashboard, modeled on the credit & A/R workflow from my LG Chem Europe internship.

SQL dbt BigQuery / DuckDB Airflow Power BI

architecture

Source (Kaggle Lending Club CSV)
   │
   ▼
Staging layer (dbt)         — typing, renaming, null handling
   │
   ▼
Intermediate layer (dbt)    — maturity-based sampling (loans issued 5+ yrs
   │                           before dataset's latest date → realistic
   │                           ~15% default rate)
   ▼
Mart layer — Star Schema    — fact_loans + dim_borrower, dim_date, dim_grade
   │                           dbt tests: not_null, unique, relationships
   ▼
Orchestration (Airflow)     — scheduled/dependency-managed runs
   │
   ▼
Power BI dashboard          — default rate, exposure, delinquency views

why this design

The dataset was deliberately sampled by loan maturity rather than used raw — taking only loans issued 5+ years before the dataset's latest date gives every loan time to reach a final status, producing a realistic ~15% default rate instead of an inflated one from including still-open loans. That judgment call is documented in the dbt model itself, not just the README.

data quality

Every mart-layer model is covered by dbt tests (not_null, unique, relationships) so a broken source feed fails the pipeline run instead of silently corrupting the dashboard — the same guarantee an Order-to-Cash team needs before trusting an aging report.

status

Staging, intermediate, and mart layers complete. Airflow orchestration and the Power BI dashboard are in progress. A planned add-on uses the Claude API to summarize dbt test failures into plain-language alerts.
